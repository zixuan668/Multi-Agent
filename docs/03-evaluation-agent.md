# 03 · 独立评审智能体

[返回项目总览](../README.md) · [协作流程与接口](multi-agent-workflow.md)

## 当前实现

真实评审入口为 `src/agents/evaluation/agent.py`，使用独立的 `prompts/evaluation/v1.1.txt` 检查同一任务的实际策略和创意，生成五维评分、风险、定向反馈、旧反馈复核与需要用户补充的信息。

输入、输出见 `packages/contracts/evaluation-request.v1.1.schema.json` 和 `evaluation-response.v1.1.schema.json`；运行校验在 `src/contracts/campaign.py`。旧 `service.py` 与 `/evaluation/demo/` 保留预设规则回放，不冒充真实模型评审。

## 评审与程序裁决

- 五维：吸引力、受众匹配、信息清晰度、渠道适配、行动引导。程序按等权平均计算综合分。
- 评分、风险及反馈复核必须引用实际字段中的原文；不接受编造证据或错误模块归属。
- 严重风险与未解决的高优先级反馈否决通过，高分不能覆盖。
- 反馈明确路由到策略或创意；评审只指出问题，不直接修改其他角色结果。
- 旧问题只有经新版本证据复核且目标内容实际改变后才能关闭，保留发现与修复的结果编号。
- 缺少试用入口等必须由用户提供的外部事实时暂停为 `awaiting_input`，不靠反复改写编造答案。

最终任务状态由后台调度决定，不信任模型自报通过。满足条件后仍为 `awaiting_confirmation`，必须由用户确认，不自动投放。

## 停止与保存

最多三轮业务优化；内容未改变、累计额度耗尽或用户取消时停止。达到上限时选择安全版本中分数最高者；全有严重风险则选择较低风险版本并要求人工复核。阶段失败也保留此前已评审版本，不丢失已有成果。

任务、反馈、事件与用量通过 SQLite 保存。重启不会自动发起收费请求，续跑需同配置且有剩余额度。

## 验证与边界

`tests/integration/test_campaigns.py` 和 `test_campaign_web.py` 覆盖真实调用路由的脚本验证、反馈关闭、伪造证据拒绝、严重风险否决、信息澄清、报告版本一致、会话隔离和重启恢复。

评分仅为投放前质量参考，不预测点击率、转化率或收益。规则无法穷尽自然语言风险，模型高分和自动测试均不能替代人工业务验收。
