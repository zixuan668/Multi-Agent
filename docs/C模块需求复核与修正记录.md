# C 模块需求复核与修正记录

日期：2026-10-19。复核依据为《智策营销软件需求规格说明书 V1.1》的 FR-006～FR-009、FR-013 与附录 C，以及《智策营销系统三人详细分工说明书 V1.0》C 模块和集成职责。另核对 README、A/B/C 模块文档、两份 B 交付说明及现有契约。文档中的旧待办不视为本次已实现功能。

## 交付对象

| 场景 | 实际交付内容 | 后续处理 |
| --- | --- | --- |
| C 发现策略问题，业务交回 A | 原始需求、当前策略、仅策略类未解决反馈与修改建议；另附创意问题、评估和完整报告供追溯 | A 修改策略并生成新版本，再交 B 更新创意、送 C 复评 |
| C 完成评估，交付用户 | 最终选中的同一组需求、策略、创意、评估与风险结论 | 通过、未达标和需人工复核均如实保留，不自动算作交回 A |
| C 开发成果交给 A 集成负责人 | 源码 ZIP、相对 B 基线的补丁、配置模板、接口和需求复核记录、测试 | A 集成公开策略修订入口、B 新策略接收和共享存储 |

页面“交回策略调整”仅在当前可继续的策略问题上出现，下载策略修改单。文件主 feedback 只含策略反馈，pending_creative_feedback 保留创意反馈，strategy_handoff 提供经过 A StrategyRequest 校验的服务层请求。当前没有 A 在线接收回执。

后续按用户反馈，默认下载改为可直接阅读和编辑的 Word 文档；上述字段属于内部快照，供系统集成。页面名称统一为“效果评估智能体”，移除模块代号。风险等级筛选现在始终显示全部、严重、中等、轻微四项数量，包括零项；按当前查看轮次统计，筛选不会改变总数。

## 修正的问题

1. 删除把所有终止结果交给 A 的逻辑；最终方案导出交用户，策略问题才交 A。
2. B 确认交付后立即进入 C，展示实际创意与真实执行阶段；不等待评分完成才跳转，不造进度和分数。重复点击与刷新不重发模型任务。
3. B 交接改成产品目标、渠道表达、四类内容、限制四项业务摘要；底部操作固定可见。
4. C 支持评估期间浏览各渠道四类创意；轮询不再每次重建预览，保留焦点与选择。
5. 修复定位在原始需求的严重约束问题误派给 B；规范化路径别名，避免重复反馈。
6. 修复跨轮历史数量/旧渠道下标导致合法新版本校验失败；历史路径按来源版本保留。
7. 增加独立反馈状态账本，只有显式合法确认才解除历史问题，保持旧记录不可变。
8. B 修订收到全部未解决创意问题，按渠道名称对应当前路径；移除渠道的历史仍保留在 C 报告。
9. 改善非法模型输出的字段修复提示，固定逻辑评估 ID 使含反馈解决记录的重放稳定。
10. 增补最终方案导出、导入来源模式和反馈账本保留；精简界面上的内部说明、版本信息与路径文本，删除桌面及移动端动效按钮和相关说明。
