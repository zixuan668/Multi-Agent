# 智策营销效果评估智能体前端制作提示词 V4 · 拟物与粒子流动版

本版依据工作区《智策营销软件需求规格说明书V1.1(1).docx》和《智策营销系统三人详细分工说明书V1.0.docx》重新设计，替代此前的通用实施效果评估提示词。本版同步用户后续要求：以 zixuan668/Multi-Agent 为基准，在 feature/evaluation-particle-workbench 分支提供独立粒子流动页面。本文件保留完整系统目标供逐项核对；当前实际交付是离线规则联调版，实现范围见 [评估工作台联调说明](evaluation-workbench.md)。

## 依据与范围

需求说明书第1章和FR-006明确：效果评估评价营销文本方案的质量与潜在风险，评分不代表真实点击率、销售额或投放收益。此前用户选择过“项目、产品或活动的实施效果”，与文档定义存在差异；本版按最新“参考文档重新设计”的要求回到文档范围，若仍需实施后效果评估，应另列需求变更。

分工说明书第5章明确组员C主责FR-006至FR-009、FR-013，以及调度、状态、配置和验收统筹。组员A主责需求及策略，组员B主责创意、界面、导出、持久化及历史查询。本次为C提供可独立演示、可交给B集成的评估前端模块。下述视觉、布局、组件组织和独立演示方式为设计建议，并非文档新增的业务规则。

## 可直接使用的制作提示词

你是一名负责智策营销系统效果评估模块的产品设计师和前端工程师。请参考上述两份文档、当前仓库的 `docs/team-collaboration.md`、公开 `packages/contracts/` 和 `src/agents/evaluation/`，制作可运行、可交互的中文“效果评估工作台”。修改限于 C 侧独立目录，保留 A 的策略入口与 B 的全站代码，通过接口适配器交接。源 Word 文档在本地工作空间，若未取得原文不得声称已重新复核。严格保留现有数据契约、评分规则、反馈路由与终止语义。不要把制作提示词的提案当成用户已经确认的业务变更。

### 01 产品定位与职责

评估营销策略和广告创意的方案质量，展示五维评分、风险、反馈、优化路径及终止结果。页面固定提示“评分为方案质量参考，不代表真实投放效果”。

本次实现C模块的专用视图与接口适配；策略、创意内容来自A/B模块或明确标注的契约样例。不得为了独立演示另造两个真实生成智能体。B负责的全站创建、持久化与历史页面通过共享组件和接口对接；独立预览壳不应被描述为完成了全站验收。

### 02 页面组成与布局

建议设置四个视图入口：评估工作台、轮次与版本、协同过程、结果汇总。顶部显示产品名称、task_id、任务执行状态、评估结论、已完成评估轮次及数据模式。

顶部展示三智能体粒子流动引擎与综合评分；中部展示五维分数、风险、反馈及系统动作；底部按页签展示不可变原始需求、策略和创意。通过版本详情查看关联 result_id。1366×768 下核心操作可见，窄屏改为纵向布局。

### 03 输入与上游内容接入

优先接收系统已有task_id及相互关联的完整策略、创意响应。独立开发演示可加载内置样例或导入UTF-8 JSON评估请求；导入是辅助入口，不是SRS强制的业务功能。首期不增加CSV/Excel业绩表、实际销量或ROI输入。

需求摘要包含product_name、product_description、marketing_goal，以及可选target_audience、budget、budget_raw、campaign_period、special_requirements。原始需求在同一任务内不可修改；更改需求应通过A负责的创建流程建立新任务。缺少预算或周期应显示信息缺口，不因此直接判为high风险。

### 04 接口与引用校验

使用附录C字段：schema_version固定1.0，task_id、agent、round_no、attempt_count、result_id、version、data、error和config_version均保持原语义。界面中文标签通过适配层映射，不改JSON键名。空数组使用[]；约定可空字段保留并使用null。

评分前校验结构、字段范围、任务归属及引用一致性：创意的strategy_result_id必须等于被评估策略的result_id，评估同时引用实际策略和创意的result_id。只做到JSON可解析不足以判定输入有效。无效输入显示字段位置，不调用模型。前端预校验辅助体验，服务端校验为最终依据。

### 05 被评估内容展示

策略展示用户画像与依据、定位、卖点及source_quote、渠道理由、预算分配、主题、推广方式、assumptions、missing_information和constraint_conflicts。

创意按渠道展示copy、slogan、poster_concept和video_script，包括场景及秒数。海报创意和视频脚本均展示为文字，不生成图片、视频文件或实际广告。内容面板提供字段定位锚点，点击评分、风险或反馈时跳到对应内容。

### 06 五维评分 FR-006

固定五个维度，不允许前端增删或调整权重：

| 中文名称 | 契约键 | 检查重点 |
| --- | --- | --- |
| 吸引力 | attraction | 开头与主题是否清晰、有吸引点且对应产品事实 |
| 用户匹配度 | audience_fit | 场景、诉求和语言是否匹配指定或明确标为推断的受众 |
| 信息传达 | clarity | 定位、卖点及必要限制是否清晰一致 |
| 渠道适配 | channel_fit | 形式、语气和结构是否符合渠道及用户约束 |
| 行动引导 | call_to_action | 下一步动作是否具体且未虚构入口或优惠 |

每项score为0至100整数，必须展示reason和target_path。总分由服务端系统代码计算五项等权平均，四舍五入保留1位；浏览器可进行一致性检查，不能以模型自报总分替代。五项不齐或数据非法时不显示伪造总分。

支持查看分档说明：0—39明显不满足，40—59关键内容缺失，60—79基本满足但有明显缺陷，80—89满足且理由充分，90—100充分满足且无明显缺陷。建议用五维条形图与明细卡片展示，图表数值与文本一致。

### 07 风险独立检查 FR-007

风险类别固定fact、constraint、compliance、brand、audience；等级为low、medium、high。每项完整展示category、severity、target_path、evidence和description，支持按类别、等级筛选。

虚构产品能力、认证、销量、优惠、效果承诺，超预算，违反必选/禁选渠道、明确周期或禁用表达等应体现为严重风险。high具有通过否决作用，界面不能因高分而弱化此提示。法律相关检查仅为风险提示。风险为空显示“本次评估未发现风险项”，不宣称保证安全或合规。

### 08 可执行反馈 FR-007

每条反馈展示feedback_id、evaluation_id、target_agent、target_path、issue、suggestion、priority和resolved。target_agent仅为strategy或creative；业务用户看到对应中文名称，开发详情中可查看原字段。

未通过时至少存在一条可执行反馈。低分但缺反馈时由调度代码按最低分维度与位置补充；无法确定归属时按策略路径处理。resolved默认false，只有后续评估确认问题消除后才改变，不能让用户勾选代替评估确认，也不覆盖原反馈文字。

### 09 反馈路由 FR-008

有策略问题：先更新策略，再基于新策略生成创意，最后重新评估；仅创意问题：保留策略result_id，更新创意并重新评估；两类问题同时出现：策略路径优先。

页面用流程箭头和事件摘要呈现反馈方向。recommended_action是模型建议，decision由系统确定性规则产生；两者分开展示，不能让建议覆盖决策。优化必须携带原始需求、当前版本与全部未解决反馈，不覆写历史有效版本。完整模式按调度自动执行，独立模式只重放已有记录或展示等待A/B接入的状态，不伪造上游生成结果。

### 10 通过与轮次终止 FR-009

通过条件为total_score达到任务冻结pass_threshold且没有high风险，默认阈值80。首次有效评估计第1轮；默认max_rounds为3，可配置1至3；有效评估完成才增加iteration_count，技术重试不增加。默认最多两次反馈优化，不产生第4轮。

达到上限：在没有high风险的有效评估中选最高分，同分选较晚版本，结论为not_passed；全部有high时，依次按high数量少、medium数量少、总分高、版本较晚选择待复核完整草稿，结论为needs_review。技术失败不自动把历史结果升格为最终通过方案。

### 11 状态与系统动作展示

分别展示任务状态、评估结论和终止原因，不把completed等同于passed。

| 状态层 | 契约值 | 界面解释 |
| --- | --- | --- |
| 任务 | pending / running / optimizing / completed / failed | 等待、执行、优化、流程结束、技术失败 |
| 评估结论 | not_evaluated / passed / not_passed / needs_review | 尚无最终结论、通过、未达标、待人工复核 |
| 终止原因 | null / passed / round_limit / technical_error / strategy_completed | 执行中、通过、轮次上限、技术错误、仅策略阶段完成 |

单次智能体响应status使用succeeded/failed，不能与任务status混用。decision保留accept、regenerate_creative、regenerate_strategy、stop_not_passed、stop_needs_review。失败和未达标分别显示下一步操作；失败重新提交产生新task_id。第一阶段仅有策略时显示not_evaluated和iteration_count=0，不能显示完成评估。

### 12 版本追踪与最终结果 FR-009及FR-010协作

每轮保存独立result_id与递增version，version不强行等于round_no。轮次视图列出五维分、总分、high/medium风险数、策略引用、创意引用与动作，支持查看历史评估。

任务级selected_evaluation_id确定最终整组策略、创意与评估；最终页面、复制文本及JSON导出都使用这组引用。选中版本可能早于最后一轮，页面同时说明“查看中的版本”和“最终选中的版本”，不混用。导出包含风险、假设、信息缺口、终止原因与剩余问题，不含密钥。Word、PDF导出不属于首期要求。

### 13 协同事件与技术重试 FR-011协作

时间线展示智能体、开始/结束/失败、评估轮次、attempt_count、时长和反馈方向。事件产生后2秒内在页面可见；可采用轮询或流式事件，具体传输方式在接口设计时确定。仅展示业务摘要和结构化结果，不展示模型内部推理。

MODEL_TIMEOUT、MODEL_UNAVAILABLE、OUTPUT_INVALID最多重试2次，即共3次尝试；等待间隔依次1秒、2秒。MODEL_AUTH_FAILED等非可重试错误不自动重试。默认超时60秒，允许10至120秒；按SRS显示超时、重试和耗尽状态。重启后未完成任务由服务端标记失败，不通过前端自动续跑掩盖中断。

### 14 配置快照 FR-013

普通用户只查看任务冻结的非敏感配置：config_version、阈值、最大轮次、超时、评分规则版本及适当的模型标识。密钥、敏感地址及受控日志不展示或导出。

管理员通过受控配置文件或环境变量维护参数；首期不设普通用户可修改的阈值滑块、模型密钥输入框或独立管理后台。配置非法阻止接单；新配置只影响新任务。不得在进行中的任务内改变评分或版本筛选口径。

### 15 与B负责的全站功能集成

提供可复用的评分面板、风险列表、反馈列表、版本表、事件时间线和配置快照组件，供B的最终方案与协同页面使用。历史记录页面的正式入口与权限由B负责，C提供评估详情和引用数据。

完整系统历史查询在服务端按会话令牌对应的owner_scope隔离，支持task_id精确查询、产品名称关键字和创建时间范围，倒序分页默认20条。前端筛选和localStorage不能替代服务端隔离或关系数据库持久化；跨会话访问显示ACCESS_DENIED。

### 16 演示模式与真实接入

本仓库本分支提供 `evaluate_bundle`、`validate_handoff`、交接校验 CLI，以及 `/api/evaluation/*` 命名空间下的离线重放服务。页面资源位于 `web/evaluation/`，启动 `python -m src.agents.evaluation.preview --port 8765`。复用现有公开策略响应；创意响应与评估契约仅为模块内提案，待 A/B 核对后发布公共 Schema。未来真实模型评分、技术重试、调度、数据库与权限由相应服务接入，本版不把预设 draft 当成模型输出。

保留现有供应商可替换配置，不因引用OpenAI Developers而强行更换模型。真实调用从后端发起，密钥不进浏览器。策略、创意未接入时，页面明确标注样例来源和未接入范围。

独立前端预览可使用“契约样例／离线重放”模式，展示五类产品以及评分、风险、路由和终止分支；预设结果只用于确定性规则演示，不能当作真实模型生成效果、完整闭环或权限验收证据。不在未授权调用范围内自动运行收费批次。

### 17 视觉与交互建议

按用户指定的 [StyleKit Neumorphism 参考](https://www.stylekit.top/styles/neumorphism/showcase#design) 制作浅灰拟物工作台。背景、面板和控件共用 #e0e5ec；左上白色高光与右下 #b8bcc2 暗影成对出现。凸起用于面板与可点击按钮，内阴影用于内容区域、输入、选中导航和按压状态。采用柔和圆角，以阴影而非边框区分层次，不使用对比色卡片、大面积渐变或按钮位移。主交互使用紫色 #6d5dfc，成功、风险、未达标用青绿、红色和琥珀文字同时注明含义；正文保持足够深度，不能因柔和阴影降低可读性。

保留三智能体节点之间的 Canvas 流动粒子和反馈弧线，颜色改为适合浅灰材质的紫色与青绿色；不能用动画冒充真实生成事件。评分环使用凸起圆盘与凹入中心，进度明确、总分和评估结论同区展示，high 风险可直接看见。粒子数量受控，后台页暂停绘制，支持手动暂停、减少动画设置和手机顶部开关。阴影状态过渡约 300ms，焦点轮廓明确。

主要操作包括加载样例、导入JSON、开始评估、刷新状态、查看定位、切换版本、复制文本及导出JSON。按钮必须实际工作或明确说明缺少哪个接口。支持键盘操作、清晰焦点、加载/空白/错误状态；不存在聊天式评估助手的必需要求，首期不额外增加自由聊天入口。

### 18 验收与交付

验收按照下表及源文档执行。前端核验计算展示、引用、定位、事件与错误交互；路由、真实重试、配置生效、权限、数据库和性能须与服务端联测。不得用前端样例演示声称全部TC通过。

| 验收编号 | 必须覆盖的情形 |
| --- | --- |
| TC-102 | 五维分、理由、位置齐全，总分与人工等权复算一致 |
| TC-103 | 虚构认证、超预算、禁用渠道触发high，不能通过 |
| TC-104 | 默认80.0无high通过；79.8或存在high不通过 |
| TC-105 | 仅创意反馈时策略result_id保持不变 |
| TC-106 | 两类反馈并存时策略先更新，创意引用新策略 |
| TC-107 | 首评第1轮，最多3轮，无第4轮；重试不计轮次 |
| TC-108 | 90分有high与78分无high并存时选后者，结论not_passed |
| TC-109 | 全部有high按风险数量及分数规则选草稿，结论needs_review |
| TC-110 | 可重试错误最多3次尝试，鉴权不重试，失败保留历史 |
| TC-111 协作 | 页面、复制及UTF-8 JSON引用同一组最终结果 |
| TC-112 协作 | 历史查询和服务端会话隔离正确 |
| TC-113 协作 | 5并发不串数据，事件2秒内可见，查询95百分位≤2秒 |
| TC-114 | 非法配置阻止接单，旧任务配置不变，中断不标成功 |
| TC-115 协作 | 五类产品各1次真实端到端流程，保留输入、结果与终止证据 |

交付可运行前端源码、启动说明、契约样例、组件与接口说明，以及实现范围和待集成项。需要后端适配时说明增补内容。保留每项验收的编号、输入/注入条件、预期结果、实际结果、配置版本和执行日期；真实调用保存模型与提示词版本等证据，敏感值脱敏。当前实现与验证记录以联调说明和测试日志为准；本提示词列出的是完整系统目标，不声称所有 TC 已完成。
