# C 效果评估页面与交付

当前功能分支已经集成 A 策略、B 创意与 C 模型评估。配置和接口见 [C模块交付与A集成说明](C模块交付与A集成说明.md)。独立离线预览不能用于证明模型效果。

## 真实使用

按 README 配置模型，运行 `python -m ops.run_evaluation_workspace --env-file <本机配置文件> --share-model --port 8767`。

1. 在 `/workspace` 提交需求，完成 A 策略，再确认交付 B。
2. 在 B 完成所有策略渠道的创意；人工修改先保存。
3. 点击交付效果评估，核对产品目标、渠道表达、四类内容与限制，再“确认交付，查看评估”。
4. 立即进入 C，可浏览刚交付的创意与实际评估阶段，完成后显示结论。刷新只恢复读取，不重复提交。
5. C 首页显示结论、综合分、五维评分、风险与建议。点击维度、风险或建议查看依据；原始需求、策略和创意默认折叠。
6. 未通过且只涉及创意时，点击“交回 B 修改创意”，定向修订后复评；涉及策略则交回 A。
7. “历史轮次”查看每轮关联版本；“方案报告”始终使用系统最终选中的关联方案，导出也使用该方案。

直接进入 `/evaluation/` 会列出同一浏览器会话的任务，不自动显示演示分数。任务地址为 `/evaluation/?task_id=...`；任务不可访问时显示错误。

## C → A

当前轮次存在策略问题且仍可继续优化时，点击“交回策略调整”，核对具体问题和修改建议，再“下载 Word 文档”。默认生成真正的 `.docx` 策略修改单，包含原始需求、策略问题、修改建议、评分风险和当前方案，A 可直接阅读编辑。当前是文件交付，A 在线接收入口待接入，不表示 A 已接收或执行。最终方案使用“导出完整方案”交付用户；通过或终止结果不一概交回 A。

系统内部策略交付快照的 delivery_type 为 strategy_feedback，包含原始需求、关联策略、创意、评估、仅策略类 feedback、pending_creative_feedback、完整报告，以及兼容 A 的 strategy_handoff 修订请求。人工阅读的 Word 修改单优先列出策略问题，创意问题单独附后；系统记录仍可从方案报告导出 JSON。人工复核、未达标和风险结论原样保留在最终方案报告。

JSON 系统记录可用“导入报告”重新查看，Word 修改单供人工阅读，不用于报告回读。导入只读取记录，不调用模型；执行失败或运行中的报告不能交付。导入校验任务引用、五维分数与平均分、完整方案及最终版本；非法报告不会替换已有结果。

## 独立离线预览

运行 `python -m src.agents.evaluation.preview --port 8765`，打开 `/evaluation/`。集成页面也可明确点击“查看演示”。演示使用预设评分草稿与规则重放，可验证风险否决、反馈分流、轮次上限和较早安全版本选择。

## 验证范围

Python 测试覆盖契约、模型错误、重试、版本与所有者隔离、反馈路由和跨轮解决状态、三轮终止和 HTTP 路由。前端测试覆盖 B 实际控制器的立即交接、重复点击及刷新恢复，C 的最终方案导出、历史查看、报告回读及失败状态。浏览器另核对真实任务、评估中创意浏览与策略修改单。详见 [需求复核记录](C模块需求复核与修正记录.md)。

服务仍在进程内保存任务，重启前须导出。全站数据库、A 在线策略修订入口和真实广告投放验证不在当前交付范围内。
