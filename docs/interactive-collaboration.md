# 三人实时协作

## 人与角色

- 李智信：策略负责人，确定受众、传播主线、事实卖点与渠道分工。
- 李莉：创意负责人，直接制作文案和视觉方案；可选先提出两个不同方向，再由用户选择深化。
- 毛小纯：独立评审，引用实际内容评分、指出问题、复核后续修复。

这三个名字对应AI角色，不是真实在场的员工。页面明确标记AI协作。生成阶段保留真实依赖关系，不为了热闹伪造同时发言或虚构争论。

## 等待时能看到什么

协作现场展示服务端真实事件：任务安排、当前阶段、技术修复、实际交付、反馈交接与用户意见。已完成阶段的结果可以立即查看，不必等最终评审。

模型适配器请求SSE流，仅读取delta.content中的公开JSON输出，抽取策略方向、创意标题/正文和评审依据等允许的字段。delta.reasoning_content不会交给UI、写入任务或作为聊天消息。展示的是公开草稿和简短依据，不是内部推理链。草稿明确标记未校验，只有通过验证后才形成正式交付。

页面每800毫秒查询任务快照，服务端公开片段约650毫秒合并保存一次；不是凭定时器演出对话或假进度百分比。请求计时仅表示已等待时长，不是预计完成时间。供应商尚未产生公开输出时，显示实际任务安排与等待状态，不编造分析。

SSE支持依据：[DeepSeek Chat Completions接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。兼容服务若不支持流式请求，可配置`MODEL_STREAMING=false`并重启，此时仍展示真实阶段与交付，不伪装成逐字输出。缺少供应商token统计时仍标记未知。

## 创意方向选择

网页创建任务始终发送`interactive=true`，保留评审后的人工检查点。默认`choose_directions=false`，直接制作首稿；选择“先选创意方向”时发送true，策略保存后生成两个提案并暂停为`awaiting_direction`。等待选择时不继续调用模型，刷新与重启保留方向。

`POST /api/campaigns/{id}/choose-direction` 接收`{option_id, base_round}`。服务端校验会话、配置、阶段、方向编号与额度。同一方向重复提交不重复启动；深化请求在公开context中接收用户选定的方向，原始交接契约保持不变。

旧API默认`interactive=false`，保留自动联调行为。

网页默认的交互模式还会在未达标评审后暂停为`awaiting_revision`。用户可以发送自己的意见，或者点击“按评审建议继续”（`POST /api/campaigns/{id}/continue-review`，空JSON）。等待用户时不运行下一轮、不继续消耗活动执行时间。这样不会在用户选择修改范围或打字时自动换轮。

## 人工意见与范围

`POST /api/campaigns/{id}/revise` 接收`{message, target_path, base_round, submission_key}`。意见1至1000字，提交标识8至100字符，服务端限制目标和当前轮次，不能由客户端提供评分或伪造上游结果。同一标识重复提交幂等，不同意见不能复用同一标识。

生成中可以留言，最多5条待处理意见。当前轮交付后转换为有来源的高优先级反馈，再交给指定角色。已结束任务在剩余额度允许时可继续精修；原始需求和已保存版本不就地覆盖。改产品事实仍需调整需求新建任务，不能通过改文案偷偷变更产品价格或能力。

整份创意修改保留策略；指定标题、正文、行动引导或视觉方案时，程序用上一版恢复其他未指定字段，再重新校验。若同时存在其他待解决反馈，相关字段也需要处理。修改策略方向则必须更新策略并重新生成关联创意。

后续独立评审必须复核人工意见；字段未实际改变不能声称已修复。达到三轮、累计请求数或活动时间上限时停止，保留结果。切换旧版本只显示该轮反馈快照，不能把后续意见混成旧轮次的发现。

遇到`awaiting_input`时，协作现场直接显示毛小纯的具体问题。用户在输入框补充已确认资料后，`POST /api/campaigns/{id}/clarify`以`{message, submission_key}`创建关联续作，保留原任务及旧事实快照，并继承已选创意方向，避免重复选方向。页面明确告知会新建续作并再次调用模型；这不是无成本地修改原始事实。若追加后超过产品介绍长度限制，会明确报错并保留输入。

## 精修与基础门槛

`quality_mode=balanced`保留综合80分、严重风险及高优先级问题否决规则。`quality_mode=polish`额外要求单项至少75分，且成品标题或正文包含产品名称；不足项形成可定位的反馈进入下一轮。它不是效果预测，也不表示消灭所有完善建议。

配置、提示词、交互规则和流式开关进入配置快照；旧配置任务仍可查看，但不能混用新配置继续生成。报告保留用户意见和方向选择，移除提交幂等标识与会话数据。

## 工作台布局与导航

新建任务按产品、目标、协作团队分区，预算等选填内容默认折叠。正文和表单使用18px字号，必要状态信息不低于16px；重复提示和历史列表时间不再占用页面。深色卡片使用明确边框、分层底色和阴影区分内容。

侧栏默认收起，顶部按钮可展开或完全隐藏，桌面端记住选择。900px及以下使用遮罩抽屉，支持关闭按钮、Escape、遮罩关闭与键盘焦点约束，选择任务后关闭；不会删除历史任务或清空需求草稿。导航独立于模型请求，不额外调用模型。

## 交付优先与资源控制

统一工作流使用一次策略生成加本地约束检查，取消固定二次策略编辑；最终评审仍核对完整策略和实际创意。默认首稿不另生成方向，正常路径三次调用，有校验修复时会增加。用户提供的产品能力按本任务事实处理，不反复要求确认同一事实。提案校验拒绝文本高度相似的方向，但这只是重复检测，不等于证明语义多样性。

明确要求申请试用、报名等转化而没有提供真实入口时，规则检查先创建零调用的`awaiting_input`任务，由李智信询问。补充事实沿用关联续作机制；泛化规则不能发现所有缺失事实，最终评审仍可能提出必要问题。

草稿评审中的账号权限、拍摄许可等执行资源问题，若定位在策略的假设、缺口或渠道计划，保存为`round.preparation_notes`，不阻断文字草稿。价格、规格、认证等事实问题不适用此规则；消费者文案中的事实追问、高风险与高优先级修改仍会阻断。原问题保留，未降低分数或风险等级。

成品默认进入创意页，需要修改时优先显示风险和具体建议，模型分数折叠。海报GET接口`/api/campaigns/{id}/poster.svg?round=1&item=0&theme=ink`校验当前会话、轮次和渠道；主题可选ink或paper。`download=1`下载SVG，浏览器从同源SVG导出1080×1440 PNG，不放宽页面CSP，不调用图片模型，不导入外部图片。草稿有标记，发布仍需人工核实。
