# 三智能体协作：实现与运行边界

## 用户流程

网页默认交互已升级为“李智信—李莉—毛小纯”的三人协作现场，含公开流式草稿、创意方向选择、人工修改检查点、定向意见与关联续作。具体状态和新增接口以[实时协作说明](interactive-collaboration.md)为准；下文基础自动闭环仍供兼容API和离线测试使用。

`python app.py` 启动统一服务。首页为产品入口，`/workspace` 为协作创作台，`/evaluation/` 为同一工作台的兼容地址。用户提交真实需求后，由策略、创意和独立评审依次执行。通过评审后等待人工确认，不自动发布或投放。

默认使用真实模型配置。`--provider offline` 是显式的规则联调模式，页面、任务快照与导出报告均保留模式标记。离线不调用模型，也不声称验证了真实创意质量。模型错误不会触发静默离线回退。

当前交付广告标题、正文、行动引导、创意理由及视觉制作方案。`assets` 必须为空；不生成图片或视频。图片工具、文件服务和视觉评审仍为后续功能。

## 角色与调用边界

- 策略：`src/agents/strategy/service.py`，基于原始需求确定定位、受众、事实卖点和渠道。复用原有生成、编辑、校验、重试及版本管理。
- 创意：`src/agents/creative/service.py`，消费成功策略，生成对应渠道的创意。不能重写原始需求、预算或渠道选择。
- 独立评审：`src/agents/evaluation/agent.py`，使用独立提示词读取实际策略和创意。输出五维评分、风险、反馈及旧反馈复核，不直接改写内容或决定任务通过。
- 后台调度：`src/backend/campaigns.py`，控制执行顺序、版本引用、反馈路由、终止、取消及人工确认。
- 公共校验：`src/contracts/campaign.py`。创意/评审的 v1.1 Schema 在 `packages/contracts/`；策略仍使用已发布的 v1.0。

三个角色可复用同一模型服务与密钥，分别使用各自的指令、数据和上下文。后台显式调用公开入口，不依靠模型自由聊天维持流程。

## 真实反馈闭环

1. 策略成功后生成创意请求。请求保留同一 task_id、原始需求和配置版本。
2. 创意结果引用当前 strategy_result_id。每个策略渠道恰好对应一项创意。
3. 评审看到实际策略/创意。评分依据与风险证据必须逐字出现在可定位的字段中；伪造引用会拒绝并要求修复。
4. 程序追加预算、事实引文、明确禁用表达及部分明显无依据承诺的硬风险。规则无法穷尽自然语言，仍保留模型评审与人工确认。
5. 仅有创意反馈时复用完整原策略，只重新生成创意。策略反馈先调用策略生成新有效版本，再生成引用新策略的创意。
6. 下一轮要求评审逐项复核所有未解决反馈。只有给出新版本证据、反馈目标内容实际改变，且同一模块没有严重风险，反馈才标记为 resolved，并记录 resolved_by 的评估结果编号。
7. 每次交接、版本保存、路由与修复确认写入事件记录。

创意请求包含完整上一创意及目标反馈；策略优化包含服务端恢复的上一有效策略。原始需求不可就地修改。用户调整需求会创建新的任务。

## 规则裁决与终止

五维等权平均保留一位小数。默认通过线80，存在严重风险或未解决的高优先级反馈时不得通过。模型不能通过输出一个 accept 字段覆盖规则。

- 达到条件：`awaiting_confirmation`，用户复核后才能转为 `approved`。
- 最多三轮：安全版本中选综合分最高者，同分选较新版本；如果全部含严重风险，按严重风险数、中等风险数、分数及轮次选择待人工复核版本。
- 新策略和创意正文都没有实际变化：停止重复调用，保留合适版本并说明原因。
- 达到总执行时间或模型调用额度：阶段失败并保留成功结果，不无限重试。
- 用户取消：取消状态立即保存，后续结果不再提交；已发出的网络请求可能仍会结束并产生供应商费用。
- 缺少必须由用户提供的外部事实：暂停为 `awaiting_input`，展示明确问题。用户补充原始事实后创建新任务，原任务与版本保持不变。

失败、中断或取消时也会保留已有评审中的最佳版本；未完成的后续轮次单独显示，不冒充完整结果。

优化轮次与技术尝试次数分开。生成/评审输出格式或证据错误最多修复三次，技术重试不自动增加业务轮次。

## 保存、恢复与执行额度

默认数据库：`artifacts/campaigns.sqlite3`，不会提交Git。可以通过 `--database` 指定独立文件。

任务、原始需求、配置快照、有效结果、反馈、事件及供应商返回的词元用量均保存。数据库连接每次使用后关闭；SQLite使用WAL模式。页面刷新可以按任务地址恢复结果。

工作空间会话使用 HttpOnly / SameSite=Strict Cookie，数据库仅保存令牌摘要，默认30天有效。其他会话不能查询或操作任务。这是本地工作空间隔离，不是完整的注册、登录和多租户账号系统。

服务重启将未结束任务标记为 `interrupted`，不会自动继续收费调用。用户选择继续后复用已成功阶段。同一提交标识与需求重复提交时复用原任务；同一标识不能对应另一份需求。

默认最多3个后台任务并行、30个运行/排队任务、同一会话最多5个活动任务。单任务最多16次模型请求、360秒活动执行时间。恢复时沿用累计模型请求额度；配置或提示词改变后需新建任务，不能混用旧快照。

记录供应商返回的 prompt_tokens 和 completion_tokens；未返回时明确标记未知。系统没有硬编码模型价格，不伪造费用金额；模型调用次数是请求数量上限，不是人民币预算。

官方DeepSeek当前模型默认显式使用 low 思考强度与8192输出上限；其他兼容服务不发送厂商专用参数。可通过受控变量 MODEL_REASONING_EFFORT 指定 low/high/max。依据：[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## HTTP接口

- GET `/api/session`：初始化或恢复工作空间会话。
- GET `/api/health`：运行模式和功能边界；配置存在不代表供应商始终可用。
- POST `/api/campaigns`：接受 `{requirements, submission_key}`，可选受控的 `quality_mode` 和 `interactive`。不接受客户端传入模型评分、阈值、轮次或上游结果。
- GET `/api/campaigns`：当前会话最近100个任务摘要。
- GET `/api/campaigns/{task_id}`：需求、阶段、版本、反馈、事件与用量。
- POST `/api/campaigns/{task_id}/cancel`：取消后续执行。
- POST `/api/campaigns/{task_id}/resume`：继续同配置的失败或中断任务。
- POST `/api/campaigns/{task_id}/approve`：人工确认通过的选中方案。
- GET `/api/campaigns/{task_id}/report?download=1`：导出报告；selected_results 的策略、创意和评估来自同一选中轮次。

修改动作使用空JSON对象。所有业务接口均要求同一会话，拒绝异源JSON提交。报告不包含密钥、原始模型响应、会话令牌、owner_scope或提交标识。

## 兼容入口与离线回放

`/strategy` 保留旧策略专用页面和API。旧的创意首轮导出仍受 v1.0 首轮契约限制，真实闭环使用新的 v1.1 交接。

`/evaluation/demo/` 与 `/api/evaluation/*` 继续提供明确标记的预设评分回放，供旧测试和交接联调使用。它们不承接业务任务，也不作为真实方案评审入口。原 `python -m src.agents.evaluation.preview --port 8766` 仍可独立启动。

## 验证与验收

```powershell
python -m unittest discover -s tests -v
node tests/frontend/test_campaign.cjs
node tests/frontend/test_evaluation.cjs
node tests/frontend/test_diagnostics.cjs
```

新增测试验证实际调用顺序、创意反馈复用策略、策略反馈更换引用、反馈复核关闭、伪造证据拒绝、高分严重风险否决、失败续跑、取消迟到结果、重复提交、会话隔离、报告引用及跨重启恢复。脚本模型测试证明程序路由行为，不等于供应商真实模型验收。

真实联调与人工广告质量验收分别记录。不得因为链路成功或模型自己评分高，就宣称广告投放效果已得到验证。
