## 交付给 A 的两类内容

**开发集成交付**是本分支源码、两份说明、候选 Schema、配置模板和测试。A 作为总集成负责人合并前，需要复核公共后端及 B 页面改动。

**业务运行交付**仅发生在策略需要调整时。Word 修改单先列策略问题与修改建议，再附原始需求、当前策略、评估依据、创意问题和当前创意，保留版本编号。系统内部另有结构化修订请求，供 A 接入生成服务。

通过、未达标或需人工复核的最终方案交给用户，不一概交回 A。下载修改单不表示 A 已接收或执行；当前没有在线接收回执。

## 数据与责任流向

原始需求 → A 策略 → B 分渠道创意 → 效果评估 → 按问题归属继续处理。

- 仅创意问题：效果评估 → B 指定字段修订 → 新创意版本 → 再评估。
- 定位、受众、渠道或预算等策略问题：效果评估准备修改单和请求 → A 更新策略 → B 基于新策略重建创意 → 再评估。后半段的网页接续仍待集成。
- 达到通过条件：交付用户最终完整方案。
- 达到轮次上限：按规则选版本，保留未达标或需人工复核结论。

原始 `task_id` 和需求在同一任务内不变。新策略、新创意必须使用递增版本和新的结果编号，不能把旧创意与新策略拼接为一份方案。模型格式修复、超时重试属于技术尝试，不增加业务轮次。

## A 和 B 仍需接续的工作

1. A 提供受会话和版本校验保护的公开策略修订入口，把 `strategy_revision_request` 交给 A 生成服务。服务层兼容性已测试，网页入口尚未接通。
2. B 提供已接收任务切换到新策略版本的路径。现有 `creative/accept` 主要是首轮接收，不能据此宣称策略优化在线闭环已完成。
3. 三方复核 B 输入、C 输出、状态映射及反馈字段，再发布正式公共协议。
4. 补齐共享数据库和重启恢复。当前任务、会话及版本仍保存在进程内存，停止服务前须导出。
5. 正式 50 例、人工质量验收、并发与 P95 性能验收、真实广告投放验证另行完成。

当前 `creative/feedback` 外部真实回调仍拒绝请求；已实现的闭环通过受信任的同进程协调器回传。独立部署成网络服务时，应另行实现服务认证与重放防护。
