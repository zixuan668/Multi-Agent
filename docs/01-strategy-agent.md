## 启动真实智能体

先把项目根目录的 `.env.example` 复制为 `.env`，填写你自己的模型服务地址、API 密钥和模型名。不要把密钥发在聊天里，也不要提交 `.env`。服务必须支持 HTTPS 的 `chat/completions` 接口和 JSON 对象输出。

在本项目目录打开 PowerShell，运行：

```powershell
python app.py
```

浏览器打开 `http://127.0.0.1:8000`。默认只使用真实模型；缺少配置会明确返回 `CONFIG_INVALID`，不静默切成模板演示。`.env` 自动读取，已有环境变量优先。配置修改后需要重启，新任务使用新快照。

页面显示“真实模型已配置”不代表连接已经验证。当前 v1.10 一次策略尝试包含决策方案生成与独立短审查，通常产生两次模型请求和相应费用；不再每次整篇重写。默认每次模型请求超时60秒，单次完整尝试最多120秒，最多3次尝试。结构、事实、明确约束及严重交付质量缺口会修复重试；轻微表达建议单列。官方 DeepSeek 当前模型默认显式使用低档思考，可用 `MODEL_REASONING_EFFORT=high` 或 `max` 调整；其他兼容服务不发送这个厂商参数。

如果暂时没有密钥，只测试页面与接口，可以显式运行：

```powershell
python app.py --provider offline
```

离线模式仍是规则演示，不具有真实模型内容理解能力。页面和测试记录都会标注，不能计入真实模型验收。按 Ctrl+C 停止服务。

## 任务与结果

### 生成与修复

提交后立即获得任务编号，后台生成并更新状态。页面展示草案生成→结构与约束校验→策略编辑与事实复核→交付的步骤，以及卖点原文依据、假设、信息缺口和冲突。每次尝试的耗时与校验结果放在修复记录中，配置等技术信息保留在任务接口与导出记录中，不在主界面堆叠展示。修复时携带完整上一次输出和具体阻断问题，不再截断长 JSON。

失败显示简短说明，具体问题、对应原文和每次修复记录折叠展示；失败任务也可导出，但不能交付创意请求。完善建议在成功结果旁单列，不写入下游业务数据契约。任务接口不暴露原始模型输出，诊断记录经过密钥脱敏。支持复制排版后的策略全文、单独复制卖点/渠道模块、导出 UTF-8 策略 JSON、导出当前任务、导出已通过首轮校验的创意请求。

### 草稿与本地归档

同一标签页刷新会恢复当前任务查询及服务端保存的原始需求，不会重新生成或追加模型调用。查询网络故障可点“恢复查询”；需求表单草稿保存在当前浏览器 localStorage 中，失败后可保留需求重新生成，也可手动清空。完成后的任务快照会进入最多 20 条的本地只读归档，即使后端进程重启仍可回看结果；它不具备多人同步、检索审计或服务端恢复能力，不能当作完整任务数据库。

### 工作台与阅读体验

工作台提供“按步骤填写 / 查看全部”两种录入模式、必填标记、5 类产品模板、周期快捷项、自然语言预算解析、日期区间或持续天数二选一校验。结果分为“策略概览 / 卖点与渠道 / 假设与信息缺口”三组，支持方向键切换；卖点依据可点击回到并高亮原始需求。摘要中的渠道数、预算分配及信息缺口数量全部来自当前任务，不展示虚构效果或评估分数；预算区明确展示已分配、总额与剩余。

历史 v1.4～v1.8 使用“草案＋策略总监整篇重写”。当前 v1.10 已替换为下述决策生成与短审查流程；旧实现仅保留兼容测试入口。离线模式仍是规则演示，不代表真实策略能力。

### 验收记录与阶段边界

2026-10-03 使用同一份“原味奶茶、附近大学生、5000 CNY、30 天、不虚构优惠、不承诺减肥效果”的真实模型单例复测成功，2 次尝试、约 64 秒。首次失败为模型额外输出 `marketing_strategy_note`，第二次通过。成功任务与创意首轮请求保存在本地 `artifacts/acceptance/` 中，此目录不提交 Git，仓库不附带这些验收报告。该记录仅证明当次单例与首轮接口通过，不代表 50 例验收、人工评估或整体可靠性已经完成。

策略完成时：`status=completed`、`assessment_status=not_evaluated`、`termination_reason=strategy_completed`、`iteration_count=0`；不表示完整方案通过评估。

第一阶段任务仅保存在当前进程，重启后清空，不提供跨重启历史。最多5个任务同时执行，内存最多1000个任务。浏览器会话令牌采用 HttpOnly / SameSite=Strict Cookie；其他会话不能查询任务。此服务默认只监听本机，是课程开发服务，不是生产部署。

内部策略模块支持带上一有效响应与反馈的优化调用，保存旧版本；旧策略网页只提供首轮入口，不开放伪造评估反馈。统一工作台由服务端恢复已持久化的有效策略并执行真实反馈优化。

约束校验分两层：程序检查金额、日期、原文引用、明确命令式渠道和引号标注的禁用表达等可确定规则；真实模型复核完整输入的语义约束及事实支持关系。自然语言规则识别和模型复核都不能证明所有内容绝对正确，仍必须按文档做人工验收。

## 四步营销简报

工作台将需求填写与策略阅读分开，默认按四步填写：

1. **产品情况**：品类、原始介绍、已确认特点、价格、销售方式与购买或咨询入口。
2. **目标与人群**：一个首要目标、希望用户采取的行动、已知人群或待验证候选、当前营销难题。
3. **执行条件**：预算、周期、已有渠道、素材与执行人力。
4. **限制与确认**：特殊限制、品牌语气，以及提交前的完整需求摘要。

必填项以“*”标记，校验问题在对应字段显示；页面不再重复显示解释段落、字数计数和步骤确认数量。资源状态区分“已知”“确认没有”和“暂不确定”；未知信息不会成为产品事实，零预算也不等同于预算待定。草稿保存在浏览器，兼容旧版字段；这不是跨设备或服务重启后的任务数据库。

公共请求的八个字段及 Schema 1.0 保持不变。`web/brief.js` 将新增上下文以 `【智策需求补充 v1】` 和带 `formVersion: 1` 的 JSON 附加在现有 `product_description`、`marketing_goal`、`special_requirements` 文本中，原始产品介绍和特点仍保留为可引用原文。v1.5 提示词解释这些状态，页面也可从归档需求还原填写内容。此附加格式属于策略模块的兼容桥接，不是新的共享 Schema；后续团队若要正式结构化扩展，应先共同更新契约与双方测试。

### v1.8 策略质量与交接补强

预算分配回归文档的“合计不超过总额”，允许保留余额，不强制把钱花完。关键词只能提示可能的执行细节缺口，不足以证明语义违规，因此改为非阻断建议；事实、超额、禁用渠道、周期及原文依据等确定性规则仍阻断。卖点依据限定为产品名称、介绍正文和明确已确认的价格；新表单把已确认价格保留在正文，兼容旧版仅存于补充 JSON 的已确认价格值。执行资源、未知价格和其他元数据不作为产品事实。

策略编辑明确区分“已记录的信息缺口/条件化执行”与“真正虚构事实”。未知价格或发布权限不应导致整份策略被拒绝；无依据的新功能或保证效果即使出现在条件句中也不能合法化。不再仅凭字段名或“核实”字样自动将事实问题降级。

对完整文本中的遗漏闭合标点、三组说明列表全部错放到 `marketing_strategy` 内的已知情况，执行有界本地修复，并记录 `syntax_repairs/review_syntax_repairs`。不补写字段值、不猜测缺失文字；重复键、未闭合字符串、供应商标记为长度截断的输出仍拒绝。修复后重新执行完整契约和事实/约束校验。明确否定的“不付费推广”不再误判为付费建议。同一技术重试的局部修复在策略编辑后继续锁定未报错字段，防止第二阶段引入无关新卖点。

任务配置与报告记录编辑器版本、校验版本及非敏感实现指纹，不再把旧 `strategy-rules-v2` 标签用于新实现。

v1.8进一步压缩冗余：定位用一句主判断，需求/痛点使用短句，优先少量不同角色的渠道；低人力零预算先做一项最小动作。不改变公共字段、数量上限或硬约束，不通过跳过复核来制造成功。

2026-10-12 工程复核：94 项 Python 自动测试、两组前端测试及9例新版表单离线契约回归通过。分轮真实检查发现并修复了复核器误把信息缺口判为违规、JSON列表错层/漏括号、已确认价格引用路径和零预算否定表达误判等问题。v1.7的一轮5例实际4例通过（其中1例重试一次），零预算例超时；v1.8修正后零预算补测一次通过，耗时102843毫秒。其他类别在前述迭代中分别出现成功结果，但未完成同一最终版本的完整五类真实回归。旧失败报告保留于本地 `artifacts/acceptance/`，不得将分轮成功拼成一次全部通过的报告。正式50例、双人人工复核及创意双方联调仍未执行；整体质量和时延不能据本次小样本宣称已验收。

### 当前 v1.10：以决策交付为中心

1. `intake.py` 将八字段中夹带的表单数据整理成内部简报，清除重复元数据与 unknown/none 下的旧资源。原始需求、公共八字段和 Schema 1.0 不变。
2. `web/examples.js` 提供五类完整虚构演示简报，区分产品介绍与特点依据，明确价格/入口、推广难题、素材、渠道和人力。示例标注为演示，不是实际商家或人工验收证据。
3. 定位负责选择、理由、取舍；渠道负责执行分工；创意任务负责受众疑问、依据、载体和行动；推广步骤负责先后、观察和调整。不能用现场点单话术代替新用户触达，资源不足要说明可实现范围。
4. `assess_strategy` 只返回可定位问题，不改整篇策略。重大目标错位、无人执行、事实错误、资源矛盾可阻断；措辞偏好和可选完善仅提示。审查证据必须来自报告字段，允许引用其数组中的字符串，不能引用别处。
5. 程序阻断明确占位输出（如只有“介绍产品”）与完全重复任务，不用关键词缺失来认定语义违规。已知假设文字包装可无损转为契约字符串；未声明的额外内容不能因此丢弃。修复不改未报告的有效字段。
6. 结果和全文复制按决策→第一步→后续反馈→渠道/创意→依据/待确认组织。完成后收起流程条；渠道文字分段展示，旧版无标签结果仍保留全文。零预算不再显示“预算待明确”。

## 下游对接

- `GET /api/session`：取得演示会话Cookie。
- `POST /api/tasks`：提交原始需求对象或只含 `requirements` 的包装，返回202及 `task_id/pending`。
- `GET /api/tasks/{task_id}`：同会话查询状态、事件及结果版本。
- `GET /api/tasks/{task_id}/creative-request`：策略成功后交付完整创意首轮请求。
- `GET /api/health`：模式与配置状态，不等同于真实连接验证。

旧 `/api/strategy` 同步入口仅保留迁移兼容，也需要会话；网页已改用异步入口。公开入口不接受客户端指定 `task_id`、`owner_scope`、轮次、配置版本或上一结果。

创意对接以 `src/agents/strategy/downstream.py` 的 `validate_creative_request` 为准，并配合 `packages/contracts/creative-request.schema.json`。它覆盖 AC-008 首轮交付，检查完整策略响应、任务归属和业务规则，不生成创意，也不冒充完整创意优化请求校验器。

## 连接模型服务

模型适配器使用通用的 `chat/completions` JSON 协议。密钥只从环境变量读取，不会写入日志或输出。

```powershell
$env:MODEL_BASE_URL='https://your-model-service.example/v1'
$env:MODEL_API_KEY='replace-with-your-key'
$env:MODEL_NAME='your-model-name'
python -m src.agents.strategy --input tests/fixtures/sample_request.json --provider compatible
```

默认 `--provider compatible`。保留的 `auto` 参数也不会再静默回退离线。模型密钥不会进入任务快照、页面或常规日志；原始输出证据只供本地测试使用。
